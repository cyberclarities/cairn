Backup — Download SQL Dump

Runs pg_dump against the live PostgreSQL database and streams the result as a compressed .sql.gz file. The dump includes DROP … IF EXISTS statements so it can be restored cleanly to any target database.

Download .sql.gz
Restore — Upload SQL Dump

Uploads a .sql or .sql.gz file produced by pg_dump and pipes it through psql to restore. Accepts dumps produced by the Download button above or by pg_dump --clean --if-exists run manually.

Destructive: this drops the schema and replaces every table with the content of the uploaded dump. A full pre-restore snapshot is taken first and its location is written to the server log, so a failed restore is recoverable — but the current data is gone the moment this completes.
Only restore a dump you produced. CAIRN checks that the file is a pg_dump of a CAIRN database at this schema version. Those are compatibility checks — they cannot tell whether the SQL inside is safe, and everything in the file runs with full database privilege. A dump handed to you by someone else is code you are choosing to execute.
Restoring… this may take a minute, please wait.
Delete a Case

Permanently deletes a case and everything on it — IOCs, evidence, timeline events, status history, and its audit trail. Alerts that were promoted or linked to the case are not deleted; they're unlinked and marked Dismissed.

Destructive and permanent. A full database snapshot is taken first, so this can be undone via Restore above if needed — but the case itself is gone the moment this completes.
Purge Old Alerts

Bulk-deletes alerts by status, source, and age — a retention tool for the alert queue rather than a one-at-a-time cleanup. A case's own record of a promoted or linked alert lives in its timeline, not the alert row itself, so purging alerts never touches a case.
